# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Site du festival **Fais comme chez toi** — Rencontres des artistes émergent·es valaisan·nes (Le Spot, Sion). One-pager **Nuxt 3 statique** piloté par le contenu : les sections sont des fichiers Markdown dans `content/`, éditables via Sveltia CMS (`/admin`). Architecture reprise de `pierreleripoll/mariaclaracastioni` (branche `staging`).

Design : maquette Figma de Siméon Dubuis, dessinée sur deux gabarits — **desktop 1280 px** et **mobile 375 px**. Les valeurs (couleurs, tailles, espacements) ont été extraites du fichier Figma via le MCP Figma, pas échantillonnées à l'œil : fond `#ffbfff`, nav `#ffc8ff`, texte `#ff00ff`, nuage `#ff7dff`. Tout est centralisé dans `assets/css/tokens.css` — c'est le point unique de re-skin, et les tailles y interpolent linéairement entre les deux gabarits.

Le fichier Figma d'origine est un **Figma Sites** (`/site/`), que le MCP Figma ne sait pas lire ; une copie en fichier *Design* classique existe et c'est celle-là qu'il faut interroger. Un second fichier, **`FCCT_2`** (`figma.com/design/x57mT9fgC6J6btgrhlmci1`), porte la maquette du menu smartphone — les autres écrans restent dans le premier.

Police : **Vevey**, servie en OTF depuis `public/fonts/` — *Positive* est le romain, *HumanKind* l'italique, les deux déclarés sous la même famille dans `tokens.css`. Repli automatique sur Quicksand si les fichiers manquent. Le disclaimer livré avec la fonte la dit *free for non-commercial use only* : à valider avec le designer avant la mise en ligne.

## Commands

```bash
npm run dev            # serveur de dev sur 0.0.0.0:3000
npm run generate       # updateImageDimensions + generateAgendaIcs + nuxt generate + verifierBuild — build canonique
npm run verifier-build # recompte les créneaux de la grille dans .output/public/index.html
npm run update-images  # régénère width/height/ratio/thumbhash dans les frontmatters
npm run update-favicons # redessine favicon.svg/.ico + apple-touch-icon depuis le nuage-menu
npm run preview        # prévisualise un build
```

Pas de tests ni de linter configurés.

## Architecture

- **One-pager.** `pages/index.vue` assemble les sections en interrogeant `content/` via `queryContent` : hero (`hero.md` — texte d'intro et liste `photos` à la racine, rendue par `components/HeroCarrousel.vue` : fondu automatique toutes les 5 s, feuilletable par deux grandes zones-flèches sur les bords, les points, et le balayage au doigt ou à la souris (pointer events, `touch-action: pan-y`) ; pause au survol et 12 s de répit après un geste, coupé par `prefers-reduced-motion` ; le cadre prend le ratio de la première photo, les suivantes se calent dedans, d'où des photos toutes au même format, 7:5 pour celles de 2025, recadrées à 2450 × 1750 depuis les originaux de 7008 px ; le crédit de la photo affichée s'écrit dessous comme celui des affiches), nuage « Appel à projet » (`appel.md`, fermable, état partagé `useState`), Artistes (`artistes/<year>.md` pour les affiches + crédit, `programme/*.md` pour les fiches artistes triées par `order` — tout filtré par l'année sélectionnée), Grille horaire (`components/SectionGrille.vue`, dérivée des `dates` des fiches par `composables/useGrille.js` — pas de source de contenu propre), Infos (`infos.md`), Partenariats (`partenariats/*.md`, triés par `order`), Participer (`participer.md`), Contact & Team (`team.md`), Soutiens (`soutiens.md`, liste de logos), pied de page (`components/PiedDePage.vue`, ligne dans `pied.md`). La nav sticky (`components/SiteNav.vue`) pointe sur les ancres de section ; dès que la ligne ne tient plus en entier dans la fenêtre (mesurée après montage, et sous 720 px d'office en CSS pour le HTML prérendu) elle devient une barre marque + **nuage-menu** (panneau plein écran) — la ligne ne défile jamais latéralement. Le nuage est une **bascule** (FCCT_2) : contour magenta sur fond de barre au repos, rempli à l'ouverture, et il reste posé par-dessus le panneau — d'où le panneau à `z-index: 0` sous la barre à 1, dans le contexte d'empilement de la nav. Le panneau n'a donc **plus de croix ni de marque en tête**, et le nuage **pas de ≡** : la maquette n'en prévoit pas, un nuage posé là où presque tous les sites mettent leur menu se lisant sans icône. Ce qui dit « bouton », c'est le **balayage** du nuage, le même que sur les textes : un second `<path>` identique, en plein, découpé par un masque en dégradé qui le parcourt (`.site-nav__nuage-balayage`, mêmes proportions et même `--balayage-cycle` que `.balayage`) ; il s'arrête à l'ouverture. Les deux tracés portent `vector-effect: non-scaling-stroke` — la propriété ne s'hérite pas, sur un `<g>` elle ne descend pas. Le tracé n'est plus celui de l'« Appel à projet » : depuis le 29.08.2026 c'est le petit nuage exporté du design pour ce bouton (`menu1.svg` fermé, `menu2.svg` ouvert, rangés dans `formulaires/maquettes/`, hors dépôt), inline dans `SiteNav.vue` avec sa boîte de 45 × 27 — fond et contour en deux tracés superposés comme dans l'export, le fond portant la lueur blanche interne (`filter#nuage-lueur`) que le contour ne doit pas subir, et l'opacité du groupe passant de 0,5 à 0,4 à l'ouverture. Un lien d'évitement « Aller au contenu » (`app.vue`) précède la nav.

- **Signaux de cliquabilité** (demandés par le design, avec deux vidéos de référence), en rose, centralisés dans `assets/css/main.css` : `.balayage` / `.section a` — le texte cliquable reste pâle et une fenêtre de lettres pleines le parcourt en boucle de gauche à droite (`background-clip: text`), à la place du soulignement ; `.balayage--fixe` (année active) le fige en plein, et au survol ou au focus le texte passe en magenta plein, balayage arrêté — c'est toute la réponse au geste. La bande de surligneur qui l'envahissait a été retirée le 29.08.2026 : un rectangle rose plein, qui se lisait comme un carré et restait collé après une tape sur écran tactile, le survol ne se retirant pas au doigt levé. `.vague` — un **reflet** traverse les cartes une à une, en ordre de lecture : un `<span class="vague">` dans les affiches, le recto des cartes artistes et les créneaux de la grille, chacun avec son rang `--i` (3 % du cycle par rang) et un `--vague-cycle` posé sur le groupe ; la grille recalcule le rang selon son nombre de colonnes (`--i-4`, `--i-2`, `--i-1`). Ce n'est plus un voile plein qui s'allume et s'éteint — trop « carré » : la bande diagonale à bords fondus vit dans `.vague::before` et s'anime en `transform`, `.vague` la rognant aux coins arrondis (`overflow: hidden`). Les surcharges de couleur se posent donc sur `--c-vague`, plus sur `background` (cf. `.creneau .vague`), et une pause d'animation vise `::before` (cf. `.carte--retournee .carte__vague::before`). Couleurs et durées dans `tokens.css` (`--c-balayage-pale` — descendu à 30 % pour que la fenêtre pleine ressorte —, `--balayage-cycle`, `--c-vague`, `--c-vague-creneau`). L'interligne du corps est un token, `--lh-body` (1,25), partagé par `body` et le verso des cartes. Les créneaux de la grille n'ont plus de plaque : couleur du fond, fine ligne en dessous (commentaire Figma #6) — ni au repos ni au survol, où le rectangle rose a disparu à son tour (29.08.2026) : seule la ligne passe au magenta plein. Les logos des soutiens (`public/uploads/logo-*.svg`) sont les **SVG noirs officiels** fournis par le design (couleur non modifiable) : servis tels quels, sans passer par `img()`/IPX (`pages/index.vue` branche sur l'extension), et gardés en `mix-blend-mode: multiply` au cas où un PNG à fond blanc arriverait par le CMS. Les sources (EPS/PDF) sont dans `formulaires/logos-sources/`, hors dépôt ; conversion : `ps2pdf -dEPSCrop` → `pdftocairo -svg` → `viewBox` resserré sur la bbox de `gs -sDEVICE=bbox` → `svgo` (avec `removeViewBox: false`, `removeDimensions`).

- **Agenda.** Chaque créneau déplié de la grille propose « Ajoute-le à ton agenda » : un `.ics` à un seul VEVENT, vrai fichier statique dans `public/agenda/` (gitignoré), généré par `scripts/generateAgendaIcs.mjs` (lancé par `npm run dev` et `npm run generate`) à partir des mêmes fiches que la grille. Un lien `data:` ne marchait pas sur iPhone — Safari iOS ignore les téléchargements `data:` — alors qu'un fichier servi en `text/calendar` (type imposé dans `public/.htaccess`) ouvre directement l'aperçu « Ajouter à Calendrier » ; le lien ne doit **pas** porter d'attribut `download`, qui casserait cet aperçu. Sur Android, où le `.ics` téléchargé demande encore d'ouvrir le fichier, le lien bascule après hydratation vers un lien « modèle » Google Agenda (`lienGoogleAgenda()`), qui ouvre l'app sur l'événement pré-rempli — détection UA en `onMounted` seulement, le HTML prérendu reste identique pour tous. `lienAgenda()` (`composables/useGrille.js`) ne fabrique que l'URL du `.ics`, `contenuIcs()` le contenu, tout déterministe (pas de `Date.now()` : UID et DTSTAMP stables, les agendas mettent à jour au lieu de dupliquer). Heure en `TZID=Europe/Zurich`, durée parsée depuis `duration` (60 min par défaut).

- **Images.** `scripts/updateImageDimensions.mjs` parcourt tout `content/` et complète les champs machine (`width`, `height`, `ratio`, `thumbhash`) de toute entrée d'image (`images[]`, `posters[]`, `logos[]`, `photos[]`, `photo`, `image`). **Ne pas éditer ces champs à la main** — lancer `npm run update-images` après tout ajout d'image. `components/ThumbhashImage.vue` (copié de mariaclaracastioni) affiche le placeholder thumbhash puis l'image responsive via `NuxtPicture`.

- **`components/ArtisteCard.vue`** — la carte « VAL-VERSO » du Figma : 323 × 437 px dans les deux gabarits (seul bloc du design qui ne s'interpole pas), recto photo + nom incrusté, verso en texte, pivot 3D entre les deux. Ses valeurs sont centralisées dans `assets/css/tokens.css` (`--card-*`, `--glow-card*`). Le carrousel de photos, lui, n'est pas dessiné dans le Figma : les points visibles sur la maquette appartiennent aux captures d'écran collées par le designer.

- **Apostrophes.** Dans Vevey, l'apostrophe droite `'` est dessinée comme un **prime** — le signe des minutes —, alors que la fonte possède bien la courbe `’`. Le contenu mélange les deux depuis toujours (tableurs, copier-coller, claviers). Le contenu a aussi le défaut inverse : les douze `duration` de 2026 écrivent leurs minutes avec la courbe (`40’`), là où il faut le bâton droit — le vrai prime U+2032 est écarté, Vevey ne le possède pas. La conversion se fait **au rendu**, pas dans les fichiers : `utils/typo.js` (`apostrophes()`, deux règles — droite → courbe entre deux lettres, courbe → droite après un chiffre) est appelé par `server/plugins/apostrophes.ts` sur le hook Nitro `content:file:beforeParse`, en dev comme au prerender, fichier entier frontmatter compris, et par `apercu/plugin.client.js` pour l'aperçu en direct. Conséquences : ne pas « corriger » les `'` de `content/`, ne pas s'étonner d'en trouver, et l'une ou l'autre saisie donne le même rendu. Les `year: '2021'` du YAML sont préservés — c'est pour ça que la règle d'élision exige une lettre de chaque côté. Les hints du CMS (`config.yml`, `aide.html`) montrent `35'` : ils doivent enseigner ce que l'éditeur verra. Le plugin Nitro importe par l'alias `~/` : un chemin relatif n'est pas résolu, Nitro le laisse externe et il se rebase sur le chunk de sortie.

- **@nuxt/content v2**, pas v3 : l'API est `queryContent()` / `<ContentRenderer :value="…">`, sans `content.config.ts` ni collections. Ne pas écrire de code Content v3 ici.

- **Provider d'images env-driven** (`nuxt.config.ts`) : IPX (sharp au build) par défaut ; `NUXT_IMAGE_PROVIDER=cloudflare` en prod Cloudflare pour transformer à la volée via `/cdn-cgi/image/`. `server/middleware/ipxCache.ts` met en cache les rendus `/_ipx/` dans `.ipx-cache` (ignoré par git), clé = URL : remplacer une image par une autre **sous le même nom** ressert donc l'ancienne — vider `.ipx-cache` dans ce cas.

- **Contrôle du build.** `npm run generate` se termine par `scripts/verifierBuild.mjs` : il recalcule la grille depuis `content/` (même `construireGrille` que le site) et compte les `class="creneau__heure"` dans `.output/public/index.html`. Un écart sort en code 1 et arrête le déploiement. Motif : le 01.09.2026 un build est parti en ligne avec une liste vide pour `queryContent('/programme')` — grille et cartes artistes disparues, aucune erreur, parce que chaque section se protège par un `v-if` ou un `|| []`. Reconstruire le même contenu a tout ramené : la panne est intermittente, pas dans les fichiers. Le workflow rejoue donc `npm run generate` une fois avant d'abandonner.

- **Déploiements.**
  - Infomaniak (seul déploiement) : `.github/workflows/deploy-infomaniak.yml`, déclenché par `dev` — deux `npm run generate` puis deux rsync de `.output/public` via SSH vers l'hébergement mutualisé Infomaniak (secrets `INFOMANIAK_*` dans GitHub ; le job se saute tant qu'ils manquent). **`faiscommecheztoi.ch`** (`INFOMANIAK_SITE_PATH`) reçoit le build public, dossier `admin/` retiré ; **`nouveau.faiscommecheztoi.ch`** (`INFOMANIAK_SITE_PATH_NOUVEAU`) reçoit le build d'édition, `NUXT_PUBLIC_APERCU=1` — admin + plugin d'aperçu + meta noindex. En production depuis la bascule d'août 2026 — le domaine a été repointé dans le Manager du dossier WordPress vers ce dossier (rollback = repointer l'ancien dossier tant qu'il existe). Servi à la racine, provider d'images IPX (build-time) — ne pas mettre `NUXT_IMAGE_PROVIDER=cloudflare`. `public/.htaccess` porte les 301 depuis les anciennes URLs WordPress, renvoie `/admin` vers `nouveau.` et pose `X-Robots-Tag: noindex` sur `nouveau.` (il branche sur l'hôte : un seul fichier pour les deux sites).
  - Cloudflare Workers (alternative, non utilisée) : `wrangler.jsonc` sert `.output/public` en static assets.

- **CMS.** `public/admin/` : Sveltia CMS, backend GitHub sur la branche `dev`, OAuth via le worker `sveltia-cms-auth` (le repo doit être autorisé dans le worker). Les images uploadées vont dans `public/uploads/`. Servi uniquement sur `nouveau.faiscommecheztoi.ch/admin`. L'interface s'appuie sur des options Sveltia ≥ 0.186 (`index.html` charge la dernière version depuis unpkg) : les sections de la page sont des `singletons` (accès direct dans la barre latérale), la liste des artistes s'ouvre filtrée sur l'édition courante (`view_filters.default` — **à déplacer chaque année** dans `config.yml`), et l'ordre se change par glisser-déposer (`reorder: {group: year}`, renuméroté édition par édition dans le champ `order`). Les items des widgets `list` (photos, logos, affiches, horaires) se glissent aussi par une poignée ≡ dans leur en-tête — comportement par défaut du widget depuis sveltia-cms#929 (commit `b21e728` du 25.08.2026, première release après la 0.198.0), rien à configurer ; les hints et `aide.html` en parlent, ne pas les faire mentir en figeant une version antérieure. Les horaires des fiches (`dates`, y compris `also.dates`) passent par un champ maison `horaire` (`public/admin/horaire.js`, `CMS.registerFieldType` — vrai React, `createClass`/`h` globaux comme dans `apercu.js`) : saisie libre remise au propre en quittant la case (le jour de la semaine est recalculé depuis le champ `year`, jamais recopié), bouton calendrier (`showPicker()` d'un `datetime-local` borné à l'année de la fiche), et `isValid()` qui bloque l'enregistrement — date illisible ou inexistante, jour de semaine faux, ou date à plus de `tolerance_jours` (7) de tout soir connu de l'édition : les autres horaires de la fiche plus `public/admin/horaires.json`, écrit au build par `generateAgendaIcs.mjs` (gitignoré). L'option `plausibilite: false` (liste `also.dates`) désactive ce dernier contrôle. Le texte enregistré reste « Je 08.10, 19:05 » (rien à migrer) et les fiches d'avant 2026 (`ANNEE_FORMAT_STRICT`) gardent leur écriture libre sans contrôle. **Le schéma de contenu est dupliqué** dans `public/admin/config.yml` : tout champ de frontmatter ajouté ou renommé doit l'être des deux côtés, sinon le CMS l'efface au premier enregistrement. Exception délibérée : les champs machine des images (`width`, `height`, `ratio`, `thumbhash`, `thumbhashRatio`) ne sont **pas** déclarés dans le CMS — Sveltia préserve les clés inconnues et `update-images` les regarnit.

- **Aperçu en direct.** Le volet d'aperçu de Sveltia montre le vrai site, mis à jour à chaque frappe. `public/admin/apercu.js` enregistre un *preview template* (Sveltia embarque React et expose `createClass`/`h` — pas de build) qui rend une iframe sur `${location.origin}/?apercu#apercu` (le hash coupe le rideau ; l'iframe de Sveltia est une URL `blob:`, d'où l'origine absolue) et lui `postMessage` `{ type: 'fcct-apercu', section, fichier, data, assets }` à chaque changement (debounce 120 ms, blobs des images fraîchement choisies via `getAsset`). Côté site, `apercu/plugin.client.js` — hors de `plugins/` exprès, enregistré dans `nuxt.config.ts` seulement si `NUXT_PUBLIC_APERCU=1` — ne s'active que dans une iframe avec `?apercu`, après `app:mounted` ; il parse le markdown avec `parseMarkdown` de `@nuxtjs/mdc/runtime` (import paresseux, même AST que le build) et pose le document dans `useState('apercu-surcharges')`, indexé par clé `useAsyncData`. `composables/useContenu.js` (`useContenu(cle, requete, { tri })`) remplace `useAsyncData` dans `pages/index.vue` et `PiedDePage.vue` et rend la surcharge quand elle existe (collections : remplacement par `_file`, puis `TRI_ORDRE` / `TRI_ANNEE_DESC`). En mode aperçu (`useApercuActif()`), `ThumbhashImage` et les logos rendent un `<img>` brut — les dérivées IPX n'existent que pour ce que le build a vu — et le ratio se mesure au chargement. Le plugin sélectionne aussi l'année et retourne la carte éditée (`useState('artistes-annee')`, `useState('artistes-ouverte')` dans `SectionArtistes`). Dev : `NUXT_PUBLIC_APERCU=1 npm run dev`.

## Conventions

- Les images de contenu vivent dans `public/uploads/`.
- Ajouter une section = un `id` dans `pages/index.vue` **et** son ancre dans `SiteNav.vue`. La hauteur de la nav (66 px) est recopiée dans le `scroll-padding-top` de `assets/css/main.css` : changer son padding oblige à mettre à jour les deux.
- Après ajout/changement d'images, toujours lancer `npm run update-images` (ou `npm run generate`).
- Le favicon est le nuage-menu seul, en magenta sur fond transparent : `scripts/generateFavicons.mjs` le redessine depuis le tracé de `SiteNav.vue` (source unique) et écrit `public/favicon.svg`, `favicon.ico` (16/32/48) et `apple-touch-icon.png`. Seule l'icône iOS garde le rose de la page derrière : le système la pose sur une tuile opaque, où une transparence virerait au noir. Ces fichiers sont commités ; relancer `npm run update-favicons` si le tracé change. Le `.htaccess` ne les touche pas — sa règle attrape-tout épargne les fichiers réels (`!-f`).
- Les fichiers `content/partenariats/` et `content/programme/` gardent un préfixe numérique dans leur nom, fixé à la création. C'est le champ `order` du frontmatter qui fait foi pour l'affichage : le réordonnancement par glisser-déposer du CMS réécrit `order` sans renommer les fichiers, le préfixe peut donc diverger — ne pas s'y fier. Pour `programme/`, l'ordre est celui de la première représentation, et le champ `year` décide sous quel onglet de la section Artistes la fiche apparaît.
- Tout tri `queryContent` sur un champ numérique doit passer `$numeric: true` — sinon les valeurs sont comparées comme des chaînes et 10 se retrouve entre 1 et 2.
- Une fiche artiste porte ses portraits dans un `photos:` **à la racine** du frontmatter (liste : la première s'affiche, les suivantes se feuillettent) : `updateImageDimensions.mjs` ne descend pas dans les objets imbriqués, un portrait rangé ailleurs serait ignoré en silence.
- Les réponses brutes des artistes (tableurs, photos originales) vivent dans `formulaires/`, hors dépôt (200 Mo, ignoré par git).
